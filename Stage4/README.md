## :gear: Agile Execution Cycle
### 1. Plan and Define Sprints
- Split development into manageable iterations.
- Use **MoSCoW** prioritization (Must/Should/Could/Won’t).
- Define sprint goals, dependencies, and responsibilities (≈ 2 weeks each).
**Deliverable:** Sprint plan document with tasks and deadlines.
---
### 2. Execute Development Tasks
- Developers follow coding standards per sprint plan.
- SCM reviews code and merges stable branches.
- QA tests completed tasks and logs bugs.
**Example:** During API sprint → build endpoints → review → test with Postman.
**Deliverable:** Functional modules + updated GitHub repo.
---
### 3. Monitor Progress and Adjust
- Hold **daily stand-ups** to review progress and blockers.
- Track work in **Trello / Jira**; measure sprint velocity and completion %.
- Adjust scope or reassign tasks as needed.
**Metrics:** velocity ≈ 14 tasks / sprint · 95 % completion · < 24 h bug resolution.
**Deliverable:** Progress report + Trello updates.
---
### 4. Conduct Sprint Reviews & Retrospectives
- Present completed features to team and stakeholders.
- Discuss what worked, what didn’t, and how to improve next sprint.
**Deliverable:** Sprint review notes + retrospective summary.
---
### 5. Final Integration & QA Testing
- Perform **end-to-end tests** verifying frontend:left_right_arrow:backend integration.
- QA validates database operations and API performance (Postman + Chrome DevTools).
- Fix bugs and confirm production readiness.
**Deliverable:** Final QA report + production-ready MVP.
